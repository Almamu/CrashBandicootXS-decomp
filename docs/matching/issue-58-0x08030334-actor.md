# Issue #58: 0x08030334-0x08031784 (actor)

25-function `decomp-chunk` covering a dense boss-weapon effect state
machine - the same large per-instance "self" object family already
documented in `actor_part17.c`/`actor_part18.c`/`actor_part19.c`
(state at `self+0x28`, a table-index at `self+0xc`, an anim-frame
halfword/byte pair at `self+0x10`/`self+0x12`, an accumulator at
`self+8`, a "part table" pointer at `self+0`, and here also an
event/trampoline table pointer at `self+0x50`), plus a second, smaller
(0x1c-byte) tracker object of the same shape pointed to by
`gUnknown_03001534` (allocated by `sub_8030F88`, left raw this pass).

The chunk generator's listed source file (`asm/code_3_2_17.s`) is
stale - by the time this issue was picked up the real raw bytes for
this address range lived in `asm/code_3_2_20_28568_c99c.s` (itself a
split-off fragment of `code_3_2_20_28568.s`). That file has now been
split further, once per matched function extracted below, following
this project's usual "cut at the boundary" convention - the split
fragments are named by the lower 5 hex digits of their first
function's address (`code_3_2_20_28568_c99c_30574.s`,
`..._30648.s`, `..._306ac.s`, `..._30d48.s`, `..._31378.s`,
`..._31504.s`, `..._31784.s`).

## Matched (7 of 25 functions)

- **`sub_8030530`** (`src/graphics/actor_part20.c`) - countdown timer
  at `self+0x54`: once it expires, plays a sound and fires the
  state-2/table-index-1 transition. Straightforward once written with
  the established `register ... asm("rN")`-pinned reset-idiom blocks
  already used throughout `actor_part19.c`'s family.
- **`sub_8030640`** (`src/graphics/actor_part21.c`) - trivial
  `self+0x68` setter.
- **`sub_80306A4`** (`src/graphics/actor_part22.c`) - trivial
  `self+0x68` getter, `sub_8030640`'s read counterpart. Needed a
  trailing `asm(".align 2, 0")` - its body is only 6 bytes, and this
  compiler doesn't emit a trailing alignment directive for a lone
  function at the end of a translation unit the way it does between
  two functions in the same file (see `matching_decomp_alignment_fix`
  memory / the alignment-padding entries elsewhere in this project).
- **`sub_8030C98`** (`src/graphics/actor_part23.c`) - advances the
  boss-weapon's screen-space accumulators, clamps a ramp value, and
  once a threshold trips, resets the small tracker object
  (`gUnknown_03001534`) to state 0 and clears `DISPCNT`'s bit 10. Hit
  a subtle instruction-*scheduling* gap: a `zero = 0` local reused for
  three separate stores (`gUnknown_03001538`/`gUnknown_0300153C`/
  `self->0xc`) needs to be **computed before** the address loads that
  consume it, matching the ROM's own evaluation order - the compiler's
  default choice puts the address load first. Fixed by pinning the
  zero constant to `r5` via `register s32 zero asm("r5") = 0;`
  declared ahead of the address loads, the same "pin the value that
  needs to out-live/out-order its neighbors" technique documented for
  register allocation elsewhere in this project.
- **`sub_80312C4`** (`src/graphics/actor_part24.c`) - toggles
  `BG2CNT` between two presets (`gUnknown_03001524`/`gUnknown_03001520`)
  and recomputes the BG2 affine matrix (uniform `scale` from
  `sub_803ADB4`, offset via `sub_8029EB4`/`sub_8029E98`). Hit the
  classic multiply-operand-order gap (`matching.md`'s recurring
  "which operand goes first" `add`/`mul` note) - writing `dy * scale`
  instead of `scale * dy` gets this compiler to put the same operand
  in the destination register the ROM does.
- **`sub_803146C`** (`src/graphics/actor_part25.c`) - boss-weapon
  "charge" countdown: while running, plays a tick sound; once it
  expires, resets the accumulator/velocity group and fires the
  state-4/table-index-1 transition on the small tracker object. Same
  "pin the constant so it's loaded before its address" gap as
  `sub_8030C98`, this time for a pair of constants (`four`/`one`
  pinned to `r1`/`r2`).
- **`sub_803171C`/`sub_8031744`** (`src/graphics/actor_part26.c`,
  contiguous pair) - a BG palette bank 1 flash-color select
  (`sub_803171C`) and a DMA-queued palette-strip animation refresh
  (`sub_8031744`) gated by `gUnknown_03001578`'s countdown. Both
  matched on the first structurally-correct attempt once written as a
  base-pointer-plus-indexed-store (`vu16 *bank1 = (vu16 *)0x05000020;
  bank1[0xf] = ...;`) rather than folding the `+0x1e` byte offset into
  a single constant - the latter makes this compiler compute a single
  literal address instead of keeping the base pointer separate the way
  the ROM does.

## Left raw (18 of 25 functions)

Everything else in this range stays in the split raw `.s` fragments
above; semantics for most of it are understood (a camera-relative
position updater pair `sub_8030334`/`sub_803044C`, a matching pair of
keyframe-table AABB lookup/dispatch helpers `sub_8030574`/
`sub_8030648`, an `InitActorPart` wrapper `sub_80305F8`, a large
weapon-kind projectile-position dispatcher `sub_80309B4`, a palette-
strip layout function `sub_8030D48`, a position-easing function
`sub_8030E08`, VRAM/tile-cache setup in `sub_8030F88`/`sub_8031040`/
`sub_8031504`, an AABB overlap test `sub_8031378`, and a palette/tile-
nibble repack loop `sub_8031604`), but this compiler's register
allocation for them diverges from the ROM's own choices in ways that
resisted real effort this pass:

- `sub_8030334`/`sub_803044C` - the camera-relative position update.
  Pinning `self` to `r6` (matching the ROM) gets most of the function
  byte-identical, but the surrounding `self->0x64` clamp/multiply
  block needs a *different* register (`r0` vs this compiler's `r7`)
  to hold the running value across the intervening camera-position
  math, and a naive attempt to also pin that value produced code that
  reused a register (`r7`) for two genuinely-overlapping live ranges
  (the cached `&gUnknown_03000884` address and the reloaded `self->0x44`
  counter) - a real correctness risk, not just a cosmetic mismatch, so
  this was abandoned rather than risk a silently-wrong "match".
- `sub_80305F8` - an `InitActorPart` wrapper. Matches ROM
  instruction-for-instruction except one 4-instruction scheduling
  permutation: this compiler always fetches an incoming 5th
  (stack-passed) parameter before processing other prologue statements,
  while the ROM's own compile does it after homing the `r6`/`r8`-pinned
  parameters. No C-level reordering tried moved the stack-argument
  fetch later.
- `sub_8030574`/`sub_8030648` - matching keyframe-table AABB lookup
  pair. A direct translation compiles to noticeably *shorter*,
  differently-structured code (this compiler proves several values
  don't need to survive in registers `r6`/`r7`, so it never pushes
  them) - reproducing the ROM's less-optimized register/stack layout
  wasn't attempted further this pass.
- The remaining functions (`sub_80306AC`, `sub_8030734`, `sub_8030834`,
  `sub_80309B4`, `sub_8030D48`, `sub_8030E08`, `sub_8030F88`,
  `sub_8031040`, `sub_80311C4`, `sub_8031378`, `sub_8031504`,
  `sub_8031604`) are large, register-pressure-heavy (frequent
  `r8`/`sb`/`sl` push/pop) functions with several still-unnamed helper
  calls (`sub_802A4F8`, `sub_802E62C`, `sub_802E674`, `sub_802E420`,
  `sub_802973C`, `sub_803B0A8`, `sub_8029B2C`, `sub_8029E34`,
  `sub_802A4EC`, `sub_802F4AC`, `sub_802E3CC`) - not attempted this
  pass given the size of the chunk; left untouched in the raw `.s`
  fragments rather than force a low-confidence match or park.
